# v0.19 — Production Readiness & Security Hardening

**Status:** Complete  
**Date:** 2026-09-03

## Objective

Prepare CampusCore for production-like environments with health checks, logging, security hardening, backup documentation, and deployment checks.

## Features Implemented

- **Health Check Endpoint**  
  `/health/` returns JSON status of database and Redis, with 200 if all ok, 503 if any service fails.
- **Logging Configuration**  
  Console and rotating file handlers; log level configurable via `LOG_LEVEL`.
- **Security Settings via Environment Variables**  
  `USE_SECURE_COOKIES=True` activates `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, HSTS, and other protections.
- **Throttling Configurable**  
  `THROTTLE_ANON_RATE` and `THROTTLE_USER_RATE` can be set in `.env`.
- **Backup Strategy Documented**  
  `docs/operations/backup.md` covers pg_dump, restore, cron scheduling, retention.
- **Production Checklist**  
  `docs/operations/production-checklist.md` lists required environment variables for production.
- **Deployment Check**  
  Ran `manage.py check --deploy`; remaining warnings are expected for development and will be resolved by production environment settings.

## Key Learning Points

- Building health checks for critical services
- Configuring Django logging with rotation
- Using environment variables to switch between dev/prod security settings
- Understanding `check --deploy` warnings
- Documenting backup and restore procedures
- Making throttling rates flexible

## How to Test

- Visit `/health/` while all services are running.
- Run `python manage.py check --deploy` to see warnings.
- Set `USE_SECURE_COOKIES=True` in `.env` and restart to see security settings apply (not recommended for local dev).
