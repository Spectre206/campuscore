# v0.9 — Redis & Celery (Asynchronous Processing)

**Status:** Complete
**Date:** 2026-09-01

## Objective

Introduce asynchronous processing using Celery with Redis as the message broker. This enables background tasks (email sending, periodic jobs) without blocking the web request, and provides a foundation for future asynchronous workloads.

## Features Implemented

- **Redis** as message broker and result backend
- **Celery** integrated with Django:
  - `config/celery.py` with Celery app
  - `config/__init__.py` loads Celery app
  - Settings: `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND`, serializers
- **Celery tasks**:
  - `send_email_task(subject, message, recipient_list)` – sends email asynchronously
  - `daily_test_task()` – periodic test task
- **Integration with academic signals**:
  - Enrollment creation → in-app notification + async email to student
  - Grade creation → in-app notification + async email to student
  - Uses `transaction.on_commit` to ensure email task queued after DB commit
- **Celery Beat**:
  - Periodic schedule for `daily_test_task` (currently set to daily at 12:00 PM)
  - Can be changed for testing
- **Email backend**: console (development), prints emails to worker console
- **Testing**:
  - Celery tasks tested in eager mode using `CELERY_TASK_ALWAYS_EAGER=True`
  - Django test email backend (`locmem`) captures outbox
  - All existing tests continue to pass (total 82+)

## Architecture

```text
Django
   │
   ▼
 Redis (broker)
   │
   ▼
Celery Worker
   │
   ▼
Background Task (e.g., send email)
```

### Processes to run

```bash
# Terminal 1: Django dev server
python manage.py runserver

# Terminal 2: Celery worker
celery -A config worker -l info

# Terminal 3: Celery beat (scheduler)
celery -A config beat -l info
```

## Key Learning Points

- Message brokers and task queues (Redis)
- Celery app configuration and autodiscovery of tasks
- Defining shared tasks with `@shared_task`
- Running worker and beat processes
- Using `transaction.on_commit` to ensure task execution after DB commit
- Celery `delay()` vs `apply_async()`
- Testing asynchronous tasks with eager mode
- Configuring Celery Beat schedules with `crontab` or interval
- Django email backend configuration (console for dev, locmem for tests)
- Retries, idempotency concepts (not yet implemented but foundation laid)

## How to Run

1. Ensure Redis is running: `redis-cli ping` → `PONG`
2. Start worker: `celery -A config worker -l info`
3. Start beat (if periodic tasks needed): `celery -A config beat -l info`
4. Start Django: `python manage.py runserver`
