# v0.12 — Docker & Containerization

**Status:** Complete
**Date:** 2026-09-02

## Objective

Containerize CampusCore with Docker and Docker Compose, creating reproducible development environments for all services: Django, PostgreSQL, Redis, Celery worker, and Celery beat.

## Features Implemented

- **Dockerfile** for the Django application
  - Based on `python:3.12-slim`
  - Installs system dependencies (`libpq-dev`, `build-essential`, `postgresql-client`, `redis-tools`)
  - Installs Python dependencies from `requirements.txt`
  - Copies project code and entrypoint script
  - Entrypoint waits for PostgreSQL and Redis readiness before starting commands
- **`.dockerignore`** to exclude unnecessary files
- **`entrypoint.sh`** script
  - Uses `pg_isready` and `redis-cli` to wait for services
- **`docker-compose.yml`**
  - Services:
    - `db` – PostgreSQL 16 with persistent volume, healthcheck
    - `redis` – Redis 7 with healthcheck
    - `web` – Django dev server, mounts project directory, exposes port 8000
    - `celery_worker` – Celery worker
    - `celery_beat` – Celery beat scheduler
  - `env_file` loads `.env`; `environment` overrides `DB_HOST`, `REDIS_HOST`, Celery URLs
  - Healthchecks ensure correct startup order
- **Environment variable handling**
  - `.env.example` created for reference
  - Actual `.env` not committed
  - `ALLOWED_HOSTS` updated to support Docker host (`0.0.0.0`)
- **Testing**:
  - Successfully built images and started all services.
  - Migrations, superuser creation, and application access work inside containers.
  - Celery worker and beat run correctly.
  - Full test suite (95 tests) passes inside Docker.

## Architecture

```text
Docker Compose
      │
      ├── Django (web)
      ├── PostgreSQL (db)
      ├── Redis (redis)
      ├── Celery Worker
      └── Celery Beat
```

## Key Learning Points

- Writing a multi-service Docker Compose setup
- Creating a Dockerfile with system dependencies and entrypoint
- Using healthchecks and `depends_on` with conditions for proper startup order
- Mounting code volume for live reload during development
- Managing environment variables between Docker Compose and Django
- Persisting database data with named volumes
- Running tests inside containers
- Using `.dockerignore` to optimize build context
- Entrypoint patterns: waiting for dependencies using CLI tools

## How to Run

```bash
# Build images
docker compose build

# Start services (detached)
docker compose up -d

# Run migrations (first time)
docker compose exec web python manage.py migrate

# Create superuser
docker compose exec web python manage.py createsuperuser

# Access app
# http://localhost:8000

# Stop services
docker compose down
```

## Testing

Run tests inside container:

```bash
docker compose exec web python manage.py test
```

All 95 tests pass.
