# v0.13 — CI/CD with GitHub Actions

**Status:** Complete
**Date:** 2026-09-02

## Objective

Automate quality checks and build processes using GitHub Actions. Every push to `main` or `develop` and every pull request runs linting, tests, and Docker build validation.

## Features Implemented

- **Linting & Formatting**
  Added Ruff configuration (`.ruff.toml`) and applied code formatting across the project.
  CI job runs:
  - `ruff check .`
  - `ruff format --check .`
- **Automated Testing**
  CI job spins up PostgreSQL and Redis service containers, installs dependencies, runs migrations, and executes the full test suite (`python manage.py test`).
- **Docker Build Validation**
  A separate job builds the Docker image after lint and test pass. It runs on push to `main` and pull requests to ensure the Dockerfile remains valid.
- **Workflow Definition**
  `.github/workflows/ci.yml` defines three jobs:
  - `lint`
  - `test`
  - `build` (needs lint and test, conditionally runs)
- **CI Status**
  After fixing formatting issues, the workflow passes: lint ✅, test ✅, build ✅ (on main/PR).

## Key Learning Points

- Writing GitHub Actions YAML syntax and structure.
- Using service containers (PostgreSQL, Redis) with health checks.
- Setting environment variables for CI and using GitHub Secrets potential.
- Running Ruff for linting and formatting.
- Running Django migrations and tests in CI.
- Building Docker image as part of CI.
- Triggering workflows on push and pull requests.
- Understanding job dependencies (`needs`) and conditional execution (`if`).

## How It Works

1. Push to `develop` triggers lint and test jobs.
2. Pull request to `main` or push to `main` triggers lint, test, and build jobs.
3. Build job ensures Dockerfile is valid.
